## 何をするものか

ツール出力・ログ・ファイル・RAG のチャンクを、**モデルに届く前に圧縮する**ローカルプロキシ。
同じ L2 にいても、OpenRouter や LiteLLM のような「どこに送るか」ではなく
「どれだけ小さくして送るか」を担当するのが他と違う点。Apache-2.0。

圧縮は元に戻せる設計になっていて、モデルが必要と判断したら元テキストを取り直せる
（Compress-Cache-Retrieve）。圧縮処理自体はローカルで完結し、外部には出ない。

## 向いている用途

エージェントのツール出力が大量に出る構成。繰り返しの多い JSON 配列やログが支配的な場面。

## 注意点

**効く相手が明確に偏る。** 公式のドキュメントが自分で列挙している範囲では、
構造の繰り返しが多い JSON やログには大きく効く一方、**コードと RAG の本文は基本的に素通し**になる。
散文は圧縮率が下がり、速度はむしろ落ちる（コスト削減にはなるが高速化にはならない）。

もう一点、ドキュメント内で数字の出所が揃っていない。トップページには出典のない大きな数値が並ぶ一方、
再現手順つきの表は別の値を示し、バージョン表記も文書間で食い違う。
**再現手順が書かれている数字だけを見るのが安全。**

## 他ツールとの関係

各エージェントへの差し込み方が製品ごとに違い、OpenCode はトランスポート差し替え、
OpenClaw は contextEngine スロット、Hermes は復元ツールのみ、と非対称になっている。
バックエンドとして OpenRouter や LiteLLM を指定できるので、この層は重ねて使える。
