OpenRouter 指標なし手動で詳細に指定

層L2・モデルアクセス層提供OpenRouter, Inc.ライセンスproprietary課金従量課金。モデル原価はパススルーで、クレジット購入時に 5.5%（Business は 8%）の手数料手動昇格の理由L2 の代表格だが公開リポジトリが無く star で測れない

何をするものか

1 本の API キーと 1 つの残高で、500 を超えるモデルに振り分けるルーター。 モデルの単価そのものには上乗せせず、クレジット購入時の手数料で収益を取る構造になっている。 2026-09 時点では、地域を EU / US 内に固定する Business ティアも用意されている。

向いている用途

複数モデルを比較したいとき。プロバイダごとに契約とキー管理を増やしたくないとき。 新しいモデルが出たときに、自分のコードを変えずに試せるのが最大の利点。

注意点

手数料には最低額があるため、少額を何度も入金すると実効レートが悪くなる。 また 可用性と遅延が自分の手を離れる。裏側のプロバイダが落ちれば影響を受ける。 未使用のクレジットには有効期限が設定されている。

他ツールとの関係

OpenCode とは層が違う。 OpenCode が「人が指示を出す面」なのに対し、 OpenRouter は「その下でモデルに繋ぎにいく中継」。両者は競合ではなく、組み合わせて使うもの。 同じ層には LiteLLM（自前でホストする OSS 版）があり、Headroom は同じ層にいながら ルーティングではなくトークン圧縮を担当する、という違いがある。

LiteLLM 勢いあり

層L2・モデルアクセス層提供BerriAIstar59,255直近リリース2026-09-20

何をするものか

100 以上のプロバイダを OpenAI 互換のインタフェースに正規化する OSS ゲートウェイ。 ライブラリとしても、独立したプロキシサーバとしても使える。近年は Rust コア + Python SDK の構成。

向いている用途

自社インフラ内にゲートウェイを置きたい場合。 モデル呼び出しのコード側を OpenAI 互換で書き切ってしまい、裏側を運用で差し替えたい場合。

注意点

自分で動かす以上、可用性とアップグレードの責任は自分に来る。 対応プロバイダが多いぶん、個々のプロバイダ固有機能の追従度には差がある。

他ツールとの関係

OpenRouter の「自前でホストする版」と考えると位置づけが掴みやすい。 Headroom は LiteLLM をバックエンドとして呼べるようになっており、層の中でさらに積み重なる関係にある。

Headroom 勢いあり

層L2・モデルアクセス層提供Headroom LabsライセンスApache-2.0star73,275直近リリース2026-08-27

何をするものか

ツール出力・ログ・ファイル・RAG のチャンクを、モデルに届く前に圧縮するローカルプロキシ。 同じ L2 にいても、OpenRouter や LiteLLM のような「どこに送るか」ではなく 「どれだけ小さくして送るか」を担当するのが他と違う点。Apache-2.0。

圧縮は元に戻せる設計になっていて、モデルが必要と判断したら元テキストを取り直せる （Compress-Cache-Retrieve）。圧縮処理自体はローカルで完結し、外部には出ない。

向いている用途

エージェントのツール出力が大量に出る構成。繰り返しの多い JSON 配列やログが支配的な場面。

注意点

効く相手が明確に偏る。 公式のドキュメントが自分で列挙している範囲では、 構造の繰り返しが多い JSON やログには大きく効く一方、コードと RAG の本文は基本的に素通しになる。 散文は圧縮率が下がり、速度はむしろ落ちる（コスト削減にはなるが高速化にはならない）。

もう一点、ドキュメント内で数字の出所が揃っていない。トップページには出典のない大きな数値が並ぶ一方、 再現手順つきの表は別の値を示し、バージョン表記も文書間で食い違う。 再現手順が書かれている数字だけを見るのが安全。

他ツールとの関係

各エージェントへの差し込み方が製品ごとに違い、OpenCode はトランスポート差し替え、 OpenClaw は contextEngine スロット、Hermes は復元ツールのみ、と非対称になっている。 バックエンドとして OpenRouter や LiteLLM を指定できるので、この層は重ねて使える。

claude-code-router 勢いあり

層L2・モデルアクセス層ライセンスMITstar37,340直近リリース2026-09-16

何をするものか

もとは Claude Code のリクエストを他社モデルへ向けるために生まれたツール。 現在は複数のエージェントを束ねるローカル制御面を名乗り、モデル横断のルーティングや ツールのオーケストレーションまで守備範囲を広げている。MIT。

向いている用途

ベンダー純正エージェントの使い勝手を保ったまま、裏のモデルだけ差し替えたい場合。

注意点

純正クライアントの想定外の使い方にあたるため、本家の更新で壊れる可能性が構造的にある。 利用規約との関係も自分で確認する必要がある。

他ツールとの関係

「エージェント本体はベンダー純正、モデルは自由」という需要を埋める位置。 最初からモデル非依存の OpenCode とは、同じ需要に別の方向から答えている。
