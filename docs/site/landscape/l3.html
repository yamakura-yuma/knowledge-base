Model Context Protocol (MCP) 現役手動で詳細に指定

層L3・共通基盤提供Agentic AI Foundation (寄贈: Anthropic)star9,262直近リリース2026-07-28手動昇格の理由star は閾値未満だが、全層が依存する接続規格のため

何をするものか

モデルとツール・データを繋ぐための接続規格。2024-11 に Anthropic が公開し、 1 年ほどで各社のエージェントが揃って実装する事実上の標準になった。 2025-12 に Linux Foundation 傘下の Agentic AI Foundation (AAIF) へ寄贈され、 特定ベンダーの持ち物ではなくなっている。

向いている用途

エージェントに社内システムを触らせるとき。一度 MCP サーバとして書けば、 対応するどのエージェントからも同じように使える。

注意点

規格が広く使われるぶん、権限設計の責任はサーバ側に来る。 エージェントに何を渡すかは MCP 自体が決めてくれるわけではない。

他ツールとの関係

L3 の中でも土台の位置にある。goose のように MCP を前提に設計されたエージェントもあれば、 後から対応した製品もある。AAIF では AGENTS.md・goose と並ぶ創立時の三本柱の一つ。

何をするものか

他ツールとの関係

AGENTS.md 現役手動で詳細に指定

層L3・共通基盤提供Agentic AI Foundation (寄贈: OpenAI)ライセンスMITstar24,513手動昇格の理由star が閾値をわずかに下回るが、AAIF 三本柱の一つのため

何をするものか

エージェントにプロジェクト固有の指示 — コーディング規約、ビルド手順、テストの流し方 — を渡すための 共通ファイル形式。ルートに AGENTS.md を置くだけ、という徹底した単純さが普及の理由になっている。

もとは Codex が「指示をどこから読むか」を決める必要から OpenAI が作ったもので、 2025-12 に AAIF へ寄贈されて中立化した。リポジトリも openai/ から agentsmd/ へ移っている。

向いている用途

複数のエージェントを使い分けている環境。ツールごとに別々の設定ファイルを書き分けなくて済む。

注意点

形式が決まっているのは「置き場所と名前」までで、中身の書き方は規定されていない。 エージェントごとに読み方の解釈が揺れる余地は残る。

他ツールとの関係

Anthropic の Agent Skills が「必要なときだけ読ませる手順書」なのに対し、 AGENTS.md は「常に読ませる前提の一枚」という違いがある。両者は排他ではない。

orca 勢いあり

層L3・共通基盤提供Stablystar73,696直近リリース2026-09-20

何をするものか

並列に走らせた複数のエージェントを束ねる ADE（agent development environment）。 デスクトップ・モバイル・リモートの各クライアントから、同じ実行環境に繋いで作業を見守る形を取る。 任意のコーディングエージェントを、自分のサブスクリプションのまま動かせることを掲げている。

向いている用途

複数のワークツリーで同時にエージェントを走らせ、その進行を一箇所で見たい場合。 手元のマシンではなく、リモートのランタイムで動かしたい場合。

注意点

エージェント本体ではなく、その外側を包む層。導入すると各エージェントの hook を書き換える形で 入り込むので、他のツールと hook の取り合いになる可能性がある。

他ツールとの関係

L1 のエージェントを置き換えるものではなく、束ねるもの。 apm が「設定を配る」のに対し、orca は「実行を束ねる」という別の役割で、 これも L3 を割り直すときの手がかりになる。

何をするものか

「一番怠惰なシニア開発者のように考えさせる」ことを掲げたスキル集。 書かなかったコードが最良のコード、という方針をエージェントに持ち込む。 特定のエージェントに縛られず、20 近いハーネスに同じ手順を配れるよう、 各社の設定ファイル形式を同梱して配布しているのが構造上の特徴。

向いている用途

エージェントが過剰に実装しようとするのを抑えたい場合。 複数のエージェントを併用していて、方針だけは揃えたい場合。

他ツールとの関係

「エージェント本体」ではなく「エージェントに配る中身」。 この形の項目が L3 に増えてきたことが、 L3 をもう一段割れそうに見える理由になっている。配布は apm のようなツールが担当する。

CodeGraph 勢いあり

層L3・共通基盤star71,617直近リリース2026-08-26

何をするものか

コードを事前にグラフとして索引しておき、各エージェントに渡すツール。 grep と Read を何度も往復する代わりに、ツール呼び出し 1 回で関連するシンボルの実体と 呼び出し経路をまとめて返すことを狙う。変更に追従して索引を更新する。

向いている用途

大きなリポジトリで、エージェントの探索がツール呼び出し回数を食っている場合。

注意点

索引を作る分の初期コストと、保持するディスク容量が要る。 索引が古いままだと、かえって誤った情報を渡すことになる。

他ツールとの関係

Headroom が「渡すものを小さくする」のに対し、CodeGraph は「そもそも探索の回数を減らす」。 どちらもトークン削減を狙うが、効かせる場所が違う。
