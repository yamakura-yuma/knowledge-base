orca 勢いあり

層L3・共通基盤提供Stablystar81,600直近リリース2026-09-29

何をするものか

並列に走らせた複数のエージェントを束ねる ADE（agent development environment）。 デスクトップ・モバイル・リモートの各クライアントから、同じ実行環境に繋いで作業を見守る形を取る。 任意のコーディングエージェントを、自分のサブスクリプションのまま動かせることを掲げている。

向いている用途

複数のワークツリーで同時にエージェントを走らせ、その進行を一箇所で見たい場合。 手元のマシンではなく、リモートのランタイムで動かしたい場合。

注意点

エージェント本体ではなく、その外側を包む層。導入すると各エージェントの hook を書き換える形で 入り込むので、他のツールと hook の取り合いになる可能性がある。

他ツールとの関係

L1 のエージェントを置き換えるものではなく、束ねるもの。 apm が「設定を配る」のに対し、orca は「実行を束ねる」という別の役割で、 これも L3 を割り直すときの手がかりになる。

Serena 現役

層L3・共通基盤提供Oraios AIライセンスGPL-3.0-or-laterstar29,907直近リリース2026-08-09

何をするものか

Oraios AI が作る、コーディングエージェント向けの MCP サーバー。IDE と同じようにシンボル単位で コードを扱う道具（シンボルの検索、参照元の検索、シンボル本体の置き換え、リネームなど）を エージェントに渡す。行番号や文字列検索ではなく、言語の意味構造に沿って読み書きさせるのが狙い。

裏側の解析は 2 通りから選ぶ。既定は各言語の Language Server（LSP）で、40 以上の言語に対応する。 もう一つは有料の JetBrains プラグインで、こちらは移動・インライン化・デバッガ操作まで使える。

向いている用途

大きめのコードベースで、ファイルをまたぐリネームや参照の洗い出しをエージェントにさせたい場合。 README は、Claude Code・Codex CLI・Copilot CLI にタスクをさせて付加価値を測った評価を載せている （評価したのは開発元自身）。

注意点

uv で入れ、serena init のあと MCP クライアントに起動コマンドを登録する。README は MCP・プラグインのマーケットプレイス経由で入れないよう明記している（載っている手順が古いため）。 言語によっては Language Server を別に入れる必要がある。

Claude Code や Codex の中で使うと、ファイル操作・検索・シェルの基本ツールは既定で無効になる （ハーネス側の道具と重なるため）。セッションをまたぐ記憶の仕組みも持つが、無効にできる。

ライセンスは部品ごとに分かれていて、本体は GPL-3.0-or-later、LSP の抽象化層（SolidLSP）は MIT。

他ツールとの関係

CodeGraph と同じく「探索の回数を減らす」側のツール。CodeGraph が事前に作った索引を引くのに対し、 Serena は起動中の Language Server に都度問い合わせる。headroom wrap を使うと既定で入る （--code-memory none で止まる）。

GraphRAG 保守

層L3・共通基盤提供MicrosoftライセンスMITstar36,198直近リリース2026-09-24

何をするものか

Microsoft Research の研究プロジェクト。非構造のテキストから LLM でエンティティと関係を抽出して ナレッジグラフを作り、そのグラフを使って質問への回答用の文脈を組み立てる。 データの前処理（索引づけ）と、それを引く問い合わせの 2 段に分かれ、どちらも CLI から回せる。

向いている用途

手元の非公開文書の集まりについて、個々の断片ではなく全体を横断した問いに答えさせたい場合。 公式ドキュメントは、既定のプロンプトのままでは良い結果が出にくいとして、 データに合わせたプロンプトの調整を強く勧めている。

注意点

README は索引づけが高コストになりうると警告し、手順とコストを読んでから小さく始めるよう 勧めている。取り込む量に比例して LLM を呼ぶため、従量課金の API では費用が嵩む。

2026-08 に README へ告知が入り、プロジェクトは実質的に保守モードになった。新しい PR と新機能は 受け付けず、バグ修正と依存関係の更新（特に CVE 対応）だけを続ける。コードは実演用で、 Microsoft の正式にサポートされた製品ではないとも明記している。

マイナーバージョンが上がるたびに graphrag init --force で設定を作り直す必要があり、 メジャーバージョンでは移行用のノートブックを流さないと再索引になる。

他ツールとの関係

「文書から一括でグラフを作る」系統の本家筋。LightRAG はこれを軽くした系統で、graphify も 同じ発想に立つ。会話から増分で記憶を積む Graphiti・Mem0・cognee とは、グラフを作る単位が違う。

LightRAG 現役

層L3・共通基盤提供HKUDSライセンスMITstar39,926直近リリース2026-09-02

何をするものか

香港大学のデータ知能研究室（HKUDS）が作る、ナレッジグラフを使う RAG フレームワーク。 README は自らを Microsoft GraphRAG の効率的な代替と位置づける。文書からエンティティと関係を 抽出してグラフにし、グラフとベクトル埋め込みの 2 層で検索する。

Web UI と REST API を持つサーバー（lightrag-server）と、Python ライブラリの 2 通りで使える。

向いている用途

文書の集まりにグラフ型の RAG を試したいが、GraphRAG の構築・問い合わせのコストは避けたい場合。 README は、GraphRAG のようなコミュニティ要約に頼らないことで、索引づけと問い合わせの両方で LLM の呼び出し回数を大きく減らすと説明している。文書の追加に合わせた増分更新と、 文書を消したときのグラフの作り直しにも対応する。

注意点

LLM への要求は通常の RAG より高い（エンティティと関係の抽出をさせるため）。抽出・問い合わせ・ キーワード抽出などの役割ごとに別のモデルを割り当てる設定で、抽出には思考モードを切った速いモデルを 勧めている。埋め込みモデルも要る。

既定の保存先はメモリ上の DB とローカルファイルで、README は小規模な試験用であり本番向けではないと 明記している。本番では PostgreSQL（推奨）や Neo4j などの外部ストレージを立てる。

他ツールとの関係

GraphRAG を軽くした系統で、同じ「文書から一括でグラフを作る」側にいる。graphify も同じ発想。 会話から記憶を積む Graphiti・Mem0・cognee とは用途が違う。

cognee 勢いあり

層L3・共通基盤提供TopoteretesライセンスApache-2.0star31,225直近リリース2026-09-29

何をするものか

Topoteretes が作る、エージェント向けの OSS の記憶基盤。文書・コード・会話を取り込み、 テキストはエンティティ・関係・検索用の断片に、コードはシンボルと依存関係のグラフにして持つ。 問い合わせ時にはグラフ・ベクトル・コードの文脈から関係するものを選んで返す。

操作は remember（記憶する）・recall（引き出す）・improve（フィードバックやセッションの内容を グラフに反映する）・forget（消す）の 4 つ。Python・TypeScript の SDK、REST API、MCP サーバーのほか、 Claude Code と Codex 向けのプラグインがある。

向いている用途

エージェントにセッションをまたいだ長期の記憶を持たせたい場合。文書とコードと会話を同じ グラフに入れたいときに、Graphiti や Mem0 より守備範囲が広い。

注意点

README は API キー無しでローカルに動くと謳う。その場合の抽出はローカルの GLiNER モデルと ローカルの埋め込みモデルで行い、LLM を使う改善の段は飛ばされ、回答文の生成はしない。 付属の GLiNER 抽出器はデモ扱いで、精度の高い版は商用の問い合わせ先に誘導している。 LLM のキーを設定すると既定は OpenAI になり、処理と回答のたびにプロバイダを呼ぶ。

グラフ・ベクトル・セッション・メタデータを Postgres 1 つにまとめる構成は、README 上ではデモ機能で、 本番向けはライセンス製品とされている。

他ツールとの関係

Graphiti・Mem0・Letta と同じ「エージェントの記憶」の系統。README はそれらからの記憶の移行手段を 案内している。文書から一括でグラフを作る GraphRAG・LightRAG・graphify とは、増分で積み続ける点が違う。

Mem0 勢いあり

層L3・共通基盤提供Mem0ライセンスApache-2.0star66,323直近リリース2026-09-25

何をするものか

Mem0 社が作る、AI アシスタントやエージェントに差し込む記憶層。会話から利用者の好みや事実を 抽出して保存し、次の会話で関係する記憶を検索して文脈に足す。記憶はユーザー・セッション・ エージェントの単位で持てる。

2026-04 に記憶の抽出方式を改め、LLM を 1 回だけ呼び、記憶を追加だけする方式（更新・削除をせず、 上書きせずに積み増す）に変えた。検索は意味・キーワード（BM25）・エンティティを組み合わせる。

向いている用途

何をするものか

Zep が作る、時間の流れを持つナレッジグラフ。エージェントとの会話や入力を「エピソード」として 取り込み、事実ごとに有効期間を持たせて、古くなった事実を自動で無効にする。 検索は埋め込み・キーワード（BM25）・グラフ探索の組み合わせ。

向いている用途

利用者や状況について、時間とともに変わる事実をエージェントに持ち越させたい場合。

注意点

Neo4j・FalkorDB などのグラフ DB と、取り込み用の LLM・埋め込みのプロバイダが要る。 既定は OpenAI で、Anthropic を使う場合も API キーを渡す（従量課金）。 README は GraphRAG との比較表で、静的な文書の要約を GraphRAG の用途として自分と区別しており、 手元の文書やコードを要約・索引する用途には向かない。

他ツールとの関係

Mem0・cognee・Letta と同じ「エージェントの記憶」の系統。文書から一括でグラフを作る GraphRAG・LightRAG・graphify とは、増分で更新し続ける点が違う。
