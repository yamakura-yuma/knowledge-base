## 何をするものか

香港大学のデータ知能研究室（HKUDS）が作る、ナレッジグラフを使う RAG フレームワーク。
README は自らを Microsoft GraphRAG の効率的な代替と位置づける。文書からエンティティと関係を
抽出してグラフにし、グラフとベクトル埋め込みの 2 層で検索する。

Web UI と REST API を持つサーバー（`lightrag-server`）と、Python ライブラリの 2 通りで使える。

## 向いている用途

文書の集まりにグラフ型の RAG を試したいが、GraphRAG の構築・問い合わせのコストは避けたい場合。
README は、GraphRAG のようなコミュニティ要約に頼らないことで、索引づけと問い合わせの両方で
LLM の呼び出し回数を大きく減らすと説明している。文書の追加に合わせた増分更新と、
文書を消したときのグラフの作り直しにも対応する。

## 注意点

LLM への要求は通常の RAG より高い（エンティティと関係の抽出をさせるため）。抽出・問い合わせ・
キーワード抽出などの役割ごとに別のモデルを割り当てる設定で、抽出には思考モードを切った速いモデルを
勧めている。埋め込みモデルも要る。

既定の保存先はメモリ上の DB とローカルファイルで、README は小規模な試験用であり本番向けではないと
明記している。本番では PostgreSQL（推奨）や Neo4j などの外部ストレージを立てる。

## 他ツールとの関係

GraphRAG を軽くした系統で、同じ「文書から一括でグラフを作る」側にいる。graphify も同じ発想。
会話から記憶を積む Graphiti・Mem0・cognee とは用途が違う。
